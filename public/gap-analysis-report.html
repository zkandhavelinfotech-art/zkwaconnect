🎯 Strategic Executive Objective
Self-Service Onboarding Standard

The strategic imperative is to upgrade ZKWAConnect from a conventional settings page into a full-fledged Native WhatsApp Business Account (WABA) Onboarding & Management Module matching the enterprise customer experience of AiSensy and Interakt.

💡
Core Differentiator: A customer signs up, navigates to Settings → WhatsApp Business API, clicks Connect with Meta, completes Meta-hosted Embedded Signup v4, and returns to ZKWAConnect with their active WhatsApp number immediately connected without manual configuration or token handling.
⚠️
Critical November 2026 Mandate: Architecture must strictly conform to Embedded Signup v4 (taking mandatory effect October 15, 2026), replacing legacy v2/v3 token exchange patterns with the Tech Provider authorization model.
⚖️ Architectural Boundary: Platform vs Customer Setup
Two-Tier Responsibility

🏢 ZKWAConnect Platform Setup (One-Time)

Configured once by ZKWAConnect SaaS engineering. Customers never see or manage these assets.

  • Meta Developer Account: Verified ZK Company Developer profile.
  • Meta Business App: Business-type app (ID: NEXT_PUBLIC_META_APP_ID).
  • Tech Provider Verification: Completed Meta Tech Provider review.
  • Login for Business & Embedded Signup v4: Configured OAuth callback URLs & configuration ID.
  • Advanced Access Permissions: whatsapp_business_management, whatsapp_business_messaging.
  • Webhook Endpoint: Webhook listener subscribed to messages, message_template_status_update, account_update.

👤 Customer Onboarding (Per Tenant / Self-Service)

Executed by customer admins through the guided Meta modal directly inside ZKWAConnect.

  • Business Portfolio: Customer selects an existing Portfolio or creates a new one.
  • WABA Account: Creates new WABA or links existing corporate WABA.
  • WhatsApp Business Profile: Display name, category, website, business description.
  • Phone Number & OTP: Enters eligible phone number and completes SMS/Voice OTP.
  • Asset Delegation: Authorizes ZKWAConnect to send/receive messages on their behalf.
  • Automated Registration: System registers phone number with 6-digit pin via Cloud API.

🗄️ Multi-Tenant Database Architecture Design
Strict Tenant Isolation

To guarantee multi-tenancy security, enterprise auditing, and resilient retries, the database schema expands from the minimal legacy models to dedicated audit-ready tables:

1. MetaAppConfigurations
Platform-level credentials for ZKWAConnect's Meta Developer App (App ID, Secret hash, Config ID, Graph API version, Tech Provider ID).
2. MetaBusinessAccounts
Tenant business portfolio records (Business ID, legal business name, country, verification status, and timezone).
3. WhatsAppBusinessAccounts
WABA metadata (wabaId, organizationId, currency, quality rating, messaging tier, display name approval).
4. WhatsAppPhoneNumbers
Verified numbers (phoneNumberId, displayPhoneNumber, callingEnabled, registrationStatus, qualityRating, limit).
5. WhatsAppOnboardingSessions
Active onboarding instances (tenantId, sessionId, currentStatus, failureReason, retryCount, startedAt, completedAt).
6. WhatsAppCredentials
Encrypted access tokens, token types, expiry timestamps, and system user ID references. Never exposed to frontend.
7. WhatsAppWebhooks
Subscribed WABA events, webhook verification status, delivery health, and last ping timestamp.
8. WhatsAppOnboardingLogs
Immutable audit logs: timestamps, raw Meta error codes (internal only), sanitized client messages, operator IDs.
9. WhatsAppManualRequests
Super admin intervention tickets generated when automated onboarding fails, enabling delegated support setup.
🔄 14-Stage Lifecycle State Machine
Fault-Tolerant Engine

Every onboarding attempt transitions through deterministic states with clear client recovery actions:

Lifecycle Status System Meaning Client Action / UI Response
NOT_STARTED No onboarding has been initiated for this workspace. Display "Connect with Meta" CTA & Readiness Checklist.
INITIATED Onboarding session generated, pre-checks verified. Launch Meta Embedded Signup modal dialog.
META_AUTH_PENDING Waiting for customer to authenticate with Facebook. Prompt user to complete FB login popup.
BUSINESS_SELECTION Customer selecting or creating Business Portfolio. Guided modal instructions in Meta window.
WABA_CREATION_PENDING WABA account name & display profile being submitted. Progress bar shown on client portal.
PHONE_NUMBER_PENDING Phone number input screen open inside Meta modal. Customer enters eligible 10-digit number.
OTP_VERIFICATION_PENDING Meta sent SMS/Voice OTP to provided phone. Customer enters 6-digit OTP code in modal.
REGISTRATION_PENDING Backend calling /{phone_id}/register Cloud API. Spinner: "Registering phone with WhatsApp network…"
DISPLAY_NAME_PENDING Display name under Meta review (number can still send). Notice: "Display name under standard Meta review."
CONNECTED WABA, Phone ID, Token, and Webhooks fully operational. Show connected badge, phone number, health metrics.
ACTION_REQUIRED Customer input required (e.g. incorrect OTP, invalid website). Show friendly resolution button (e.g. "Retry OTP").
FAILED Technical failure (timeout, network, permission issue). Show sanitized error and "Retry" / "Request Help".
MANUAL_REVIEW Customer flagged for Super Admin assisted setup. Support ticket created; admin notified on console.
SUSPENDED Meta policy restriction or suspended business status. Alert banner directing customer to Meta Business Manager.
📋 Pre-Onboarding Business Readiness Checklist
Prevents Meta Modal Drop-Off

Before launching the Meta Embedded Signup modal, ZKWAConnect runs an interactive pre-flight checklist:

✓
Fresh / Eligible Phone Number Must NOT be currently active on standard WhatsApp or WhatsApp Business App on a phone (or must be deleted from app first).
✓
Legal Business Entity & Details Legal business name, registered corporate address, official email, and GSTIN / PAN / Registration certificate.
✓
Live Public Business Website Functional HTTPS website displaying business contact information and privacy policy.
✓
Meta Business Portfolio Admin Access The Facebook user logging in must hold Full Control / Admin access to the company's Meta Business Portfolio.
👑 Super Admin Console (SaaS Product Owner Delegation)
Managed White-Glove Onboarding

Delegated Tenant Onboarding Features:

  • Tenant Workspace Provisioning: Create customer tenant workspace and initiate managed onboarding in 1 click.
  • Onboarding Session Inspection: Real-time visibility into every tenant's active step, drop-off point, and Meta error code.
  • Sanitized vs Raw Error Duality: Customer sees clean friendly guidance; Admin sees exact Meta Graph API code and error subcode.
  • Manual Asset Verification: Validate customer-provided WABA IDs, Phone IDs, and system user tokens without bypassing OAuth security.
  • Support Ticket Integration: Auto-generates high-priority support ticket when MANUAL_REVIEW is triggered.

🛡️ Security Rule: Strict Token Privacy

Admins cannot bypass Meta authorization by arbitrarily entering arbitrary WABA IDs or phone numbers. All connections must originate from cryptographically verified Meta OAuth tokens or authorized Partner System User asset shares.
